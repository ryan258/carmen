## State transitions

`idle → investigation → between → investigation … → final → complete`

- Continue case is the primary returning-player action, including a trusted-manifest pack switch when needed; asynchronous loading rechecks the saved snapshot. Investigation starts with the case file and puzzle available. A saved `clues` tab opens the case file. The active task precedes the collapsible route, and original evidence is available beside puzzle/arrest decisions with optional saved useful-clue marks.
- Correct puzzle and final answers wait for explicit Continue, including after resume. The warrant unlocks only after a correct answer. Catalog-3 arrests prefill the established answers for explicit confirmation. Catalog-1/2 runs preserve their manual warrants: compact pairing retains the full cross-product and separate fields remain available. Both layouts lock during feedback.
- Wrong input locks until feedback ends; input handlers enforce phase as well as disabled controls.
- A successful warrant awards points and records one capture, saves the **between** phase at the same index, and shows the APPROVED stamp briefly (none under reduced motion) before the report appears. Between stops, players deduce the suspect's destination from the seized lead or travel stub and select from three seeded destination choices. Choosing an incorrect location costs one life unless assisted (never taking the last life, keeping at least 1 life in the transition screen) and disables that choice; choosing the correct location advances to the next stop. At the final stop, the between screen leads directly to the final report.
- Catalog-3 ordinary reports, Classic and Mixed, are three four-choice reviews of the selected first, middle, and last stops' cases with that case's clues shown; they never test recall of tokens, route order, or suspect details. Catalog-1/2 saves keep their historical finale: Classic ends on the last stop's token; Mixed orders four evenly spaced visited stops and matches their tokens. The Swapped Dispatch starts Mixed and instead uses three authored four-choice synthesis decisions with all recovered records visible. All report work takes place at headquarters.
- Activity card selections save immediately. Undo last and Clear work are free. Ordering/matching require all cards, assembly requires the stated fragment count, and filtering accepts any nonempty subset for checking. Each distinct rejected answer costs one life until assistance is enabled; repeating a rejected answer costs nothing. Filtering compares unordered sets; other activities preserve order. Feedback identifies a position/condition to review. Solved activities wait for Continue.
- At zero lives, Continue with support preserves the investigation without future life loss; Pause and keep case retains the save; explicit closure records the unfinished outcome. Enabling support during play also preserves prior work and permanently marks the result assisted. Terminal handlers are idempotent; record/stat writes identify the run. Only explicit closure clears an unfinished case.
- Restart, title navigation, new runs, and pack replacement cancel pending session callbacks. Dialogs pause delayed delivery. Pack loading blocks start/resume until the latest request settles or falls back.
- Any existing save requires an explicit replacement choice before a new case starts. Keep saved case receives initial focus. Confirmation is bound to the exact saved value, selected pack, and route; Escape and storage events invalidate it.

## Scoring

Puzzle points are 100/75/50 for zero/one/two previous mistakes, then 25. Each charged hint subtracts 15 from puzzle credit, with a 25-point floor. `hintsUsedInRound` and `totalHintsUsed` count all revealed hints; `scoringHintsUsedInRound` increments only while `supportEnabled` is false. Enabling support never refunds previous deductions or changes already earned points. It permits up to three hints, including during the finale, without further hint deductions, and `assisted` prevents further life loss. Warrants award 50. From the third consecutive capture, the streak bonus is `(streak − 2) × 25`; a rejected legacy warrant resets the streak. Completion adds 200 plus 50 per remaining life. An unassisted perfect game adds 500 for every puzzle solved first try with no lost lives. Hints alone do not disqualify that bonus; assistance does.

Catalog-3 completion commendations use first-try successful stops divided by the chosen route length: 100% Chief Inspector, at least 75% Senior Detective, at least 50% Detective, otherwise Case Investigator. Assistance adds an explicit label without lowering the commendation. Four-stop and eight-stop routes use the same proportions. An explicitly closed incomplete run receives an ended-outcome label. Catalog-1/2 runs retain historical score-based ranks.

Records compare only the same pack/content version/life allowance/stop count/route offset/quiz format/catalog, plus rule revision, assisted status, reasoning preference, and episode identity. Catalog-3 Classic records retain catalog 3 because their overlays and arrest flow differ; historical Classic records normalize to catalog 1. Valid older records without a format remain Classic prefix records, and older Mixed records retain their catalog interpretation. Aggregate pack statistics remain totals across formats. These are local convenience data, not secure rankings.

## Persistence and boundaries

New saves use schema 8 and catalog 3. Besides the established phase, content identity, case IDs, route offset, score ledger, lives, history, tokens, attempts, answer/card order, warrant state, and activity progress, schema 8 requires `assisted`, `supportEnabled`, `challenge: standard | advanced`, nullable `episodeId`, `evidenceMarks`, and `scoringHintsUsedInRound`. Support implies assistance. Scoring-hint count cannot exceed revealed hints and must equal them when support is off. Evidence marks contain unique current clue indices 0–2. Episode identity resolves only trusted content and must match its exact four-stop route and case IDs. Activity IDs, indices, rejected answers, and phase/score consistency are validated against trusted descriptors, never imported questions.

Valid matching-content schemas 5, 6 and 7 resume. Schema 5 remains Classic; schema 6 retains its format and original twenty-activity catalog. Both keep their prefix route and normalize to route offset 0/catalog 1. Schema 7 retains its explicit route and catalog 1/2. Historical manual warrants, case IDs, eliminated options, scores, and partial activity work retain their original interpretation. On the next write, schema 8 adds unassisted/support-off defaults, standard reasoning, no episode, no clue marks, and a scoring-hint count equal to prior hints. Historical schemas reject injected new-contract fields. Older builds cannot read schema 8. Invalid, foreign, unsupported, or different-content saves remain rejected without mutation. Pack IDs and content versions are unchanged.

Recent-case history stores at most 100 known unique identities per pack/content version, oldest to newest. A case enters history only after its investigation opens and successfully saves, including in an abandoned run. Planned future cases do not. Given a seed, history, and catalog, selection is deterministic; persisted case IDs are authoritative on resume.

Catalogs 2 and 3 assign distinct fictional hideout/disguise labels within each location of the eight text-heavy packs, consistently across clues, hints, controls, and explanations. Canonical answer values remain the persisted/scored identity; catalog-1 runs retain original wording. These are fictional teaching labels, not new factual claims about actual sites or staff.

Study is an unscored title-screen workflow with case selection, stars, optional notes, worked answers, 48 companion transfers, and optional Again/Got it review scheduling. Its bounded notebook is separate from game progress. Backup exports the notebook and saved case as JSON; import validates the format, previews compatibility, and requires separate explicit notebook/save replacement actions tied to the inspected storage snapshots. It imports no pack content, settings, scripts, or HTML. Optional read-aloud uses only a selected installed local voice. A missing voice leaves the complete text available.

The pack validator checks the runtime shape, identity/version fields, coordinates, options, unique IDs/tokens, source references, metadata, and basic markup restrictions. Only repository-owned pack JSON is supported. The markup restrictions are a guardrail, not a general HTML sanitizer. User-authored uploads require a separate design.

Packs contain 4–100 locations and every supported route contains at least four stops. Route options, save validation, and the finale share this minimum. The bundled eight-location packs offer 4/6/8 stops. The base pack contract still requires one four-choice answer per case; optional activity alternatives live in `quiz-activities.js`, guarded by exact pack ID, content version, and case ID. Mismatched versions fall back to the original case. No pack JSON, authoring generator, or fallback snapshot changed for the activity addition.

The optional map distinguishes a pending library, a failed library, failed tiles, and a deliberately selected text route. Library readiness redraws only an active, visible game. Retry map reuses the pinned CDN URL and integrity attributes, permits only one pending library retry, and respects the Text route preference. Map failures do not change saved progress.

The regular page loads seventeen local runtime scripts, including `case-design.js`, `game-experience.js`, and `game-career.js`. An optional `npm run build:offline` produces one portable HTML file with those scripts, styles, and all pack data, excludes remote executable resources, and uses the text route. It does not prefetch map tiles, register a service worker, or contact a source until the user follows its link. Local-file persistence is browser-dependent; notebook/save backup supports recovery. The offline artifact has been rebuilt at `dist/carmen-offline.html` and verified.

Storage errors switch to session memory with a warning. Save writes, terminal cleanup and abort confirmation check ownership of the saved snapshot; storage events close dialogs and cancel stale sessions. This is a single-save convenience model, not a cross-tab transaction system. No telemetry, server storage, authentication, or external AI calls are part of the game. External map/CDN requests are described in the dependency plan.

## Accessibility and verification boundary

These implementations still require the browser and assistive-technology checks in the QA documents. They do not constitute a conformance claim.

## Career layer

`game-career.js` adds cross-run progression in its own `carmen_career` storage key: XP, level, badges, closed-pack IDs, the last 500 counted run IDs, and about 60 days of daily outcomes. Each run counts once. **Play today's case** starts a four-stop Mixed detective run seeded `daily-YYYY-MM-DD` in the selected pack; one daily per local calendar day across all packs. Closing with support still counts as solved. Study reviews earn career XP once per case per local day; results can queue missed stops into the notebook as due Again entries, refusing to write over an unreadable notebook. The career card counts due reviews for the selected pack. Saves, records, and stats are unchanged. Clipboard copy of the daily grid is local and optional.
